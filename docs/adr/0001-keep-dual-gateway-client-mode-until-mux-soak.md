# Keep the `dual` gateway client mode until the mux soak completes

`RITHMIC_GATEWAY_CLIENT_MODE=dual` (one `GatewayClient` socket per consumer) stays as the rollback path for the default `mux` mode (`GatewayRuntime` + `GatewayMux`, one shared socket per credential fingerprint). Architecture review proposed deleting the flag and the dual-only branches now; that was rejected because `docs/plans/2026-09-01-001-feat-gateway-runtime-migration-plan.md` (R6, U5) makes removal conditional on a soak of 10 RTH sessions or two calendar weeks, and `GatewayClient` itself cannot be deleted either — `MuxGatewayClient` subclasses it and the lake, scripts and tests construct it directly. What *was* done: the byte-identical socket and framing code both modes carried now lives once in `rithmic_gateway/framed_conn.py` (`FramedConnection`); the RPC and polling cores stay separate because they are genuinely different designs (inline read vs drain thread with per-request waiters).
